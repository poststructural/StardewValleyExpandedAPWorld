# StardewArchipelago co-op feasibility survey
Root: .cache/stardew_archipelago/StardewArchipelago (paths relative to it). ~13.6k LOC, 17 patcher files, ~478 Harmony Patch() calls. Our patches (patches/mod/0001-0005) touch nothing multiplayer-related.

## 1. Connection model
- Connection is created in ModEntry.OnSaveLoaded (ModEntry.cs:261) -> ReadPersistentArchipelagoData (443) -> AttemptConnectionToArchipelago (349) -> InitializeAfterConnection (285; builds ~25 managers and applies all Harmony patches, 285-345). New game: OnSaveCreating (~185) refuses to create without a live connection; the connection comes from the title-screen AP connect UI (ArchipelagoConnect, 598) / ArchipelagoConnectionOverride (99).
- Connection info lives in ArchipelagoStateDto.APConnectionInfo (Serialization/ArchipelagoStateDto.cs:10: ip, port, slot, password), persisted with helper.Data.WriteSaveData("ArchipelagoData") at ModEntry.cs:211 and :238 (OnSaving). Separate save keys for AP experience and friendship (AP_EXPERIENCE_KEY, AP_FRIENDSHIP_KEY, ModEntry.cs:57-59).
- Farmhand today: SMAPI's ReadSaveData/WriteSaveData throw InvalidOperationException for a non-main player (StardewModdingAPI.xml:9427, 9434 in _testbed/sdv-sve). So on a farmhand OnSaveLoaded throws at ModEntry.cs:445; the catch (ModEntry.cs:276-281) prints "A Fatal error has occurred while initializing Archipelago" and rethrows. Result: no connection, no patches installed, farmhand plays near-vanilla inside the host's modified world. A crash, not a clean block.
- Existing guard: none (no Context.IsMainPlayer / IsMultiplayer in ModEntry). Tester feature "Multiplayer" (GameModifications/Testing/TesterFeatures.cs:14, AdvancedOptionsManager.cs:106 sets Game1.startingCabins) is only a debug option. "MultiplayerVision" (GameModifications/MultiplayerVision/*, StardewArchipelagoClient.cs:36,89,214,523) is NOT SDV multiplayer: it draws other AP slots as ghosts via AP Bounce packets.
- Docs: goal.md marks several goals "Coopable" meaning several separate saves/clients sharing one slot, not one farm.

## 3. Item receipt
- Pipeline: StardewArchipelagoClient -> OnItemReceived (ModEntry.cs:588) -> APItemManager.ProcessItem (Items/APItemManager.cs:28) -> ItemParser -> LetterAttachment.SendToPlayer -> Mailman.SendMail (Items/Mail/Mailman.cs ~185). Letters use Game1.addMailForTomorrow (Game1.cs:9485: local farmer only unless sendToEveryone) or Game1.mailbox/Game1.player.mailReceived. Effects fire when the LETTER IS OPENED (MailPatcher.ExitThisMenu_ApplyLetterAction_Postfix, MailPatcher.cs ~70 -> Items/Mail/LetterActions.cs). Receipt is inherently per-farmer: only the opener is affected, and dedupe uses Game1.player.hasOrWillReceiveMail (Mailman.cs:45,56,67).
- Per-farmer in SDV (must reach every farmer): backpack (LetterActions.cs:111-138), tools/upgrades/trash can (:260-311), keys/talisman/club card/translation/golden scythe (:143-195), friendship points (:101-105), cooking/crafting recipes (:684-701; SkillUnlockManager.cs:216), skills/levels/masteries (SkillUnlockManager loops Game1.getAllFarmers() :53-207 but writes farmer.farmingLevel on REMOTE farmers; remote Farmer netfields are owned by their peer so host-side writes will likely not sync -> must run on each owning client), equipment/weapons (:674), buffs (PlayerBuffInjections), book stats (BookUnlockManager.cs:43), trinket slots.
- Team/world-shared (apply once on host): money (shared wallet), island unlocks (addMailForTomorrow(..., sendToEveryone:true) already at LetterActions.cs:520-602; netWorldState.ParrotPlatformsUnlocked :576), CC bundles, raccoon flags via MasterPlayer (VanillaUnlockManager.cs:174-190), farm cave (LetterActions.cs:249), building unlocks, seasons (SeasonsRandomizer/State.SeasonsOrder), traps (TrapExecutor, 87 Game1.player refs), DeathLink (DeathManager.cs:41 loops all farmers).
- State.ItemsReceived is one global processed list, so a second client processing the same list would replay every item unless a per-farmer cursor exists.

## 4. Saved state
- ArchipelagoStateDto via SMAPI save data (host-only API; ModEntry.cs:211-213,238-240): conn info incl. password, ItemsReceived, LocationsChecked, JojaLocationsChecked, LocationsScouted, LettersGenerated (also injected into Data/mail by Mailman ctor, Mailman.cs:22-30), SeasonsOrder, EntrancesTraversed, Wallet, TrapsState, bundle/raccoon status etc.
- Farmhands cannot read or write it. Letter text, checked list, seasons order etc. must be pushed to farmhands (mod message) or rebuilt from the AP server. Farmer.modData (synced to host and persisted in host save) is a good per-farmer store (processed-item cursor, per-farmer AP xp/friendship); helper.Data.WriteJsonFile is the client-local alternative.

## 5. Harmony patches that misbehave on a farmhand
All 478 patches are installed in InitializeAfterConnection, so on a farmhand today they are absent (vanilla drops, vanilla warps, no checks). If installed on farmhands:
- Host-gated already (fine): MountainInjections.cs:47, WalnutPuzzleInjections, ObjectNudger.cs:335, TemporaryBabyInjections.cs:177.
- World mutations must be host-only or they duplicate: FarmInjections.PlaceAutoBuildings/DeleteStartingDebris/ForcePetIfNeeded (ModEntry.cs:501-503), map edits (IslandWestMapInjections), bundle completion, NoHouseInjections, BugFixer.
- Per-client data assets need identical inputs (SlotData, checked list, seeds) or shops/festivals/NPC appearance desync: Data/Shops invalidate (ModEntry.cs:525), FestivalDataModifier, RecipeDataRemover (loops all farmers), AppearanceRandomizer, ArchipelagoLocationDataDefinition custom item type (every peer needs the mod to deserialize such items).
- Per-day/per-tick work would run on all clients: ModEntry.cs:462-531 (OnDayStarted jobs: SendTrustFundLetter, DayUpdateDebt, traps) and :547-577 (trap dequeue, MovementInjections, MultiplayerVision, FoolVision); ChatForwarder/commands would double-forward.
- Statics: injections hold static _archipelago/_locationChecker/_state fields and static dicts (friendship, xp, buffs, cookie clicker Wallet, MovementInjections). Splitscreen shares one process so per-player statics need PerScreen<T>.

## 7. Recommended design
A) "Every client connects" (recommended MVP, least code): AP allows N connections to one slot. Host sends connection info to farmhands via helper.Multiplayer.SendMessage (e.g. type "ap.hello": ip/port/slot/password plus State fields farmhands need: SeasonsOrder, LettersGenerated, EntrancesTraversed). Farmhand runs the existing InitializeAfterConnection with a synthetic State and no SMAPI save data; per-farmer cursor in Farmer.modData. Server dedupes checks and rebroadcasts them so checked lists converge without relaying. Each client turns received items into letters (already per-farmer). Add an ItemScope table: TEAM items (money, island unlocks, buildings, bundles, seasons, raccoon/cave, optionally traps) applied only when Context.IsMainPlayer; PER-FARMER items applied by every client. Risks: password in transit, farmhand needs network route to AP server, DeathLink/traps fire n times, transient checked-state disagreement, host must load before farmhand.
B) "Host only, relay" (cleaner, ~1.7x code): farmhand uses a RelayLocationChecker : ILocationChecker that mod-messages check names to the host; host mirrors checked list and received items to peers and sends ApplyItem(name, uniqueId) so each peer runs the letter locally. Single AP session, no credential sharing, no duplicate traps. Cost: farmhand needs a replica of StardewArchipelagoClient (SlotData used 625 times, ScoutedLocations, DataPackageCache) so SlotData and datapackage must be serialized and hints/scouts/!!commands proxied.
Both need: (1) Context.IsMainPlayer branch in OnSaveLoaded (ModEntry.cs:261) and guards on every ReadSaveData/WriteSaveData; (2) host-only gating of world mutations and per-day jobs; (3) per-farmer/PerScreen rewrites of static dicts; (4) a team-vs-per-farmer classification of ~60 unlock handlers.
Size: ~15-25 files touched, +1.5k LOC (A) to +2.5k LOC (B). Breakdown: protocol/MultiplayerManager 300-400; farmhand bootstrap + synthetic State 250; item scope table + edits to VanillaUnlockManager/SkillUnlockManager/ToolUnlockManager/LetterActions 300-400; per-farmer xp/friendship 150; host gating of patches/day jobs 150-250. No unit-test seam for Game1, so most effort is manual two-instance testing (LAN or splitscreen).
Riskiest: (1) host writes to remote Farmer fields not syncing (SkillUnlockManager); (2) static singletons vs splitscreen; (3) DayEnding timing (shipping/goal checks, MultiSleepManager vs SDV all-sleep); (4) shop/asset divergence between clients; (5) bundle UI in multiplayer where CC state is host-owned; (6) trap semantics with N players; (7) new-game flow (only host creates slot save; cabins; farmhand custom AP mail).
Cannot reasonably work faithfully: per-farmer unlocks (recipes, skills, professions, friendship/hearts, tools/backpack, books) can only be "everyone gets each progressive item" - a design rule, not true AP semantics; "who earned it" for Friendsanity/Fishsanity/Cooksanity collapses to "anyone"; goals based on one farmer's stats (Perfection, Master Angler, Full House, Greatest Walnut Hunter) need a rule (host's farmer or any); separate-wallet shipping bins; farmhands need the same mod versions.
Suggested first step: prototype A on LAN: guard OnSaveLoaded, farmhand hello + connect, gate TEAM items on host, test one item + one check round trip before touching UI hooks.
