# Plan: co-op on one Archipelago slot (2026-11-04)

Goal: two or more people play one Stardew Valley Archipelago slot on one shared farm (online or LAN
co-op), with SVE. Today the client is host-only by design, and a farmhand who joins an AP save gets a
caught crash and plays near-vanilla. Survey notes: `docs/coop-survey.md`.

## How it would work for players

- The host creates the AP save as usual. Friends join through the normal Co-op menu with the same mods.
- Every farmer's actions count: a fish caught or a recipe cooked by any farmer sends the check.
- Items are **shared**. Team things (money, bundles, island, seasons, traps) happen once. Personal
  things (backpack, tools, recipes, skills, hearts) go to **every** farmer, because Stardew keeps
  those per farmer.
- Farmhands never type connection details. The host's game hands them over when they join.

## Design: every client connects (recommended)

The AP server already accepts several connections to one slot and ignores duplicate checks, so each
game connects on its own and nothing needs relaying.

1. **Join handshake.** When a farmhand's game loads, it stops reading host-only save data (that is the
   crash today). It asks the host over SMAPI mod messages, and the host replies with the connection info
   and a read-only snapshot of the mod state (checked list, letters, seasons order).
2. **Same client pipeline on the farmhand.** The farmhand connects and runs the existing check hooks, so
   per-farmer actions (fishing, cooking, crafting, friendship, skills, museum, shops, quests, eating,
   festivals) send checks with no per-hook rewrite.
3. **Item scope table.** Every received item is tagged *team* (the host applies it once) or *per-farmer*
   (each game applies it to its own farmer). Each farmer keeps its own "items applied up to N" cursor in
   `Farmer.modData`, which is saved with the host's save, so nothing is replayed or skipped.
4. **Host-only world changes.** Patches that change the shared world (buildings, debris, pet, map edits,
   day-start money and debt, trap dequeue, chat forwarding) are gated to the host. Patches that edit
   data assets (shops, festivals) must give identical results on every client and are checked for that.
5. **Splitscreen** is a stretch goal, because the client keeps state in statics that would need
   per-screen copies.

The alternative is to keep only the host connected and relay farmhand checks through it. That keeps
the password off farmhands' machines, but it is about 1.7x the code, because the farmhand would need a
copy of the client's slot logic. I'd only switch if sharing the password matters to you.

## What can't be exact

- "Who earned it" becomes "anyone on the farm".
- Progressive personal items are given to everyone (each farmer gets the backpack upgrade, etc.).
- Goals that read one farmer's stats (e.g. skill mastery) use the host's stats.
- Separate-wallet games: shipping still counts, but money items go to the shared wallet only.

## Phases

| Phase | What | Done when |
|---|---|---|
| C1 | Farmhand no longer crashes; join handshake; farmhand connects | A farmhand joins an AP save and its SMAPI log shows a connected slot, ERROR 0 |
| C2 | Item scope table + per-farmer cursor | One team item applies once, and one per-farmer item reaches both farmers, across a save/reload |
| C3 | Host-only gating for world mutations and daily jobs | A two-player day passes with no duplicated buildings, money, debt or traps |
| C4 | Check coverage from farmhands | The smoke test, extended to two games (host + farmhand on this PC over LAN), sends each check path from the farmhand |
| C5 | Docs, release v0.2.0 beta | `docs/setup.md` has a co-op section |

## Size and risk

About 15–25 client files, roughly +1.5k lines, carried as our own mod patches. It diverges from upstream
StardewArchipelago more than anything so far, so every future upstream bump costs more to rebase.

Riskiest: writes to another farmer's fields don't sync (each effect must run on that farmer's own
game); day-end timing with several sleepers; shop and asset desync between clients; the bundle menu
when the host owns the Community Center; trap behaviour with several players; and needing two game
instances to test anything.

## Testing

Two SMAPI instances of the testbed on this PC: one hosts and one joins over LAN at `127.0.0.1`. The
smoke-test harness drives both. You and a friend do a real online session before release.

## Leaving alone

- No change to the world or the apworld. Co-op is client-only, so existing seeds work.
- Single-player behaviour stays the same. Every new path checks `Context.IsMultiplayer` / `IsMainPlayer`.
